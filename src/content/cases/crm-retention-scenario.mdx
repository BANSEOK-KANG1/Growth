## Overview

이 케이스는 퍼포먼스 마케팅 이후의 CRM/그로스 확장 가능성을 보여주기 위한 프로젝트입니다.

광고로 사용자를 데려오는 것만으로는 성장 문제가 해결되지 않습니다. 유입 이후 문의를 완료하지 않은 사용자, 문의 후 미팅으로 이어지지 않은 사용자, 미팅 후 구매하지 않은 사용자를 분리하고 각 단계에 맞는 메시지와 지표를 설계해야 합니다.

## Problem

광고비를 써서 유입을 만들었더라도 다음 구간에서 이탈이 발생하면 성과가 누수됩니다.

- 랜딩을 봤지만 문의하지 않는 사용자
- 문의했지만 미팅으로 이어지지 않는 리드
- 미팅했지만 구매하지 않는 잠재고객
- 구매했지만 재방문/재구매하지 않는 고객

이 문제를 해결하려면 광고 성과와 CRM 시나리오가 연결되어야 합니다.

## My Role

- 퍼널 단계별 이탈 세그먼트 정의
- 세그먼트별 CRM 메시지 가설 수립
- 측정 지표 정의
- 실험 우선순위 정리
- 리드 상태값 기반 후속 액션 설계

## Segmentation

| 세그먼트 | 문제 | 메시지/액션 | 측정 지표 |
|---|---|---|---|
| 광고 클릭 후 문의 미완료 | 관심은 있으나 전환 전 이탈 | 사례/혜택/FAQ 중심 리마인드 | 재방문율, CTA 클릭률 |
| 문의 완료 후 미팅 미진행 | 상담 전 이탈 | 상담 전 준비 안내, 신뢰 콘텐츠 | 미팅 전환율 |
| 미팅 후 미구매 | 의사결정 지연 | 비교표, 후기, 가격 안내 | 구매 전환율 |
| 기존 고객 | 재방문/재구매 필요 | 시즌별 혜택, 업셀 메시지 | 재구매율, LTV |

## Experiment Design

실험은 다음 구조로 설계합니다.

```txt
Segment
  → Hypothesis
  → Message
  → Channel
  → Metric
  → Decision
```

예시:

| 항목 | 내용 |
|---|---|
| Segment | 문의 완료 후 미팅 미진행 리드 |
| Hypothesis | 상담 전 신뢰 콘텐츠를 제공하면 미팅 전환율이 상승할 것이다 |
| Message | 상담 프로세스 안내 + 고객 사례 + 예상 질문 |
| Channel | 알림톡 / 이메일 / 문자 |
| Metric | 메시지 오픈율, CTA 클릭률, 미팅 전환율 |
| Decision | 미팅 전환율이 기준 대비 상승하면 자동화 시나리오로 확장 |

## Analysis

CRM의 핵심은 메시지를 많이 보내는 것이 아니라, **어떤 세그먼트에 어떤 메시지를 보내고 어떤 지표로 판단할 것인가**입니다.

퍼포먼스 마케팅과 CRM을 연결하면 다음과 같은 판단이 가능해집니다.

- 어떤 캠페인에서 유입된 사용자가 CRM 반응이 높은가?
- 어떤 리마인드 메시지가 미팅 전환을 높이는가?
- 광고 CPA가 높더라도 CRM 전환이 좋으면 유지할 수 있는가?
- 구매 전환이 낮은 세그먼트는 가격/신뢰/시기 중 무엇이 문제인가?

> 광고 유입 이후 단계별 이탈 유저를 분리하고, 각 세그먼트에 맞는 CRM 메시지와 측정 지표를 설계했습니다.

## Decision

| 실험 결과 | 판단 | 다음 액션 |
|---|---|---|
| 오픈율 높음 + 클릭률 낮음 | 제목은 반응하지만 메시지 설득 약함 | 본문/CTA 개선 |
| 클릭률 높음 + 전환 낮음 | 랜딩/상담 연결 문제 | 랜딩 또는 상담 프로세스 개선 |
| 미팅 전환 상승 | 메시지 효과 있음 | 자동화 시나리오 확장 |
| 전환 변화 없음 | 세그먼트/가설 오류 가능성 | 세그먼트 재정의 |

## Action

- 유입 이후 리드 상태값을 정의
- 문의 미완료/미팅 미진행/미구매 세그먼트 분리
- 단계별 CRM 메시지 작성
- 오픈율, 클릭률, 전환율 기준으로 실험 판단
- 성과가 있는 메시지는 자동화 시나리오로 확장

## Result / Expected Impact

이 구조를 통해 광고 유입 이후의 이탈 구간을 줄이고, 광고 성과를 단순 전환 수가 아니라 후속 전환과 LTV 관점으로 확장할 수 있습니다.

## Limitation

실제 CRM 실험은 충분한 사용자 수와 메시지 발송 인프라가 필요합니다. 따라서 포트폴리오에서는 프로젝트형 설계로 제시하고, 실제 적용 시에는 데이터 규모와 개인정보 처리 기준을 확인해야 합니다.
